**Music Video search gets sorting, filtering and a "you already have this"
badge — and stops offering you duplicates of videos you've already downloaded.**

Nothing to migrate, no settings changed.

## Sort and filter your search results

Two new controls appear above the results once you've searched:

- **Sort** — Best match (the quality ranking, as before), Most viewed, or Longest.
  Changing it re-queries the server, because the full ranked result set lives in a
  server-side cache and is paged from there.
- **Filter loaded results** — narrows what's already on screen by title or
  channel, instantly, with no round trip. The summary line says "loaded results"
  deliberately: filtering can't reach results you haven't paged in yet, so hit
  "Load More" if what you want isn't there.

## "✓ Downloaded" badge, and no more accidental duplicates

Videos you already have are now marked and dimmed in the results, with a **Hide
already downloaded** toggle to get them out of the way entirely.

**The more important half is what it prevents.** Before this release, downloading
a video you already had could create a *second* artist folder and a second Plex
collection. The cause is worth explaining, because it affects a specific and
non-obvious set of artists:

Vidshelf snaps a search query back to an existing artist folder so that searching
"Weird Al Amish Paradise" files under your existing **Weird Al** rather than
forking a new "Weird Al Amish" artist. That works by matching names — so it can't
bridge a spelling difference. Five Matchbox Twenty videos live in a folder called
`Matchbox_20`; searching **Matchbox Twenty**, the spelling the band's own uploads
use, matched nothing, reported all five as not downloaded, and downloading one
created `Matchbox_Twenty` alongside it.

Both halves are fixed by asking a different question. A YouTube video ID is
globally unique, so "do I already have this?" doesn't depend on which folder it
was filed under — and when you re-download something, the existing record says
where it went, with no spelling involved.

**One limit, stated plainly:** this fixes videos you already have. A *brand new*
Matchbox Twenty video still lands in `Matchbox_Twenty`, because there's no record
to consult. Closing that would need `20` to match `Twenty`, which would also make
`Sum 41` match `Sum Forty-One` — a worse trade.

## Two things the app was claiming that weren't true

- **"Newest" is not offered as a sort**, because it couldn't work. YouTube's
  search results don't include upload dates (measured: 0 of 34 results), so
  sorting by date returned the list untouched. An option that silently does
  nothing is worse than no option.
- **The ranking no longer claims to consider "upload recency."** It never did —
  the recency bonus was gated on that same missing upload date, so it has never
  been awarded. The README and the in-app help text both said otherwise. The
  scoring itself is unchanged; only the description was wrong.

## Housekeeping

The project is now free of unused imports and unreachable locals, and CI checks
for undefined names on every run. That check isn't cosmetic: it's what caught a
guaranteed startup crash in v1.11.0's restructuring, where a module used a name
it never imported — `import` succeeded, the existing CI import check passed, and
the function would have failed on first call during boot.

## Upgrading

```bash
docker compose pull && docker compose up -d
```

Or on Windows, `.\update.ps1`.
