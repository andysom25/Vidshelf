**Documentation and CI patch, plus one dependency bump. No behaviour changes,
nothing to migrate.**

Upgrading is optional.

## Why this exists

v1.11.0 shipped two unrelated things: the HTTP 403 download fix, and a large
internal restructuring that split five modules out of `app.py` (3,262 → 2,398
lines). The release notes covered the first and said nothing about the second,
because the 403 fix was the urgent half.

This release closes that gap. `REFERENCE.md` — the engineering log this project
keeps so the same problem is never diagnosed twice — now has the full account of
the restructuring, including four things worth knowing before touching that code:

- **Source-level invariants keyed to a filename are defeated by a refactor.** Ten
  of them read `app.py` by name. Moving code out of that file did not fail them —
  it *satisfied* them, by taking the pattern they forbid out of the file being
  read. Five of the ten protect bugs that actually shipped. Fixed before anything
  moved, and demonstrated: with violations planted in new modules, the old suite
  passed 27/27 and the new one failed on both.
- **`import x` succeeding does not mean `x` works.** An extracted module used a
  name it never imported. `import library` still succeeded, because Python
  resolves that at call time — so CI's import check stayed green while a function
  that runs during **startup** was a guaranteed crash. A static analyser found it
  in a second; no test could.
- **Rebinding a re-export does not change what the owning module sees.** Two
  regression tests substituted a fake YouTube probe by patching it on `app`. Once
  the real one moved, the code under test no longer looked there, and the tests
  silently stopped testing anything.
- **A rule that names files on disk existed in two copies.** Byte-identical,
  either editable without the other, and the first symptom would have been music
  videos retried into the wrong folder.

## Also fixed

**CI's "check every module imports" step never learned about the five new
modules.** It still listed only the pre-v1.11.0 ones, so a broken
`config_store.py`, `webauth.py`, `tracker.py`, `youtube.py` or `library.py` would
have passed CI. Given the startup-crash bug above was exactly an import-time
problem, this was the wrong check to leave stale.

`CONTRIBUTING.md` gains a "Where things live" section: what each module owns, and
two rules that are structural rather than stylistic — nothing outside `app.py` may
import it, and anything a browser waits on must have a network timeout while
downloads stay patient.

## Still to come

The routes themselves are still all in `app.py`. Moving them into blueprints needs
four more service modules extracted first (the download executor, the conversion
job state, the channel monitor and the search caches are all still app-level, and
a blueprint importing any of them would create an import cycle). `REFERENCE.md`
records the analysis so that work starts from the answer.
