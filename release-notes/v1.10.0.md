**Polish and confidence release.** The dashboard added in v1.9.0 works, but it
shipped three regressions in three consecutive patches — every one of them
something a human sees in half a second and no test in this repo could reach.
This release fixes what was still wrong and closes that gap properly.

Nothing to migrate, no settings to change.

> **Version note:** this follows v1.9.2. `1.10.0` is greater than `1.9.2` under
> semver — the minor component is a number, not a decimal, the same way Python
> 3.10 follows 3.9.

## Video titles no longer keep leftover brackets

Vidshelf strips boilerplate like "(Official Video)" from titles. It only knew how
to tidy up **parentheses** afterwards, so uploaders who use square brackets got
the wreckage left behind:

| Uploader's title | Before | Now |
|---|---|---|
| `… Planetary (GO!) [Official Video] [HD]` | `… Planetary (GO!) [] [HD]` | `… Planetary (GO!) [HD]` |
| `… I'm Not Okay [Official Video - 4K Film Restored]` | `… I'm Not Okay [ - 4K Film Restored]` | `… I'm Not Okay [4K Film Restored]` |
| `Artist - Song [Official Music Video]` | `Artist - Song []` | `Artist - Song` |

This affected the dashboard's Recently Added list immediately, and it went into
the **filename** of every music-video download from a channel that brackets its
boilerplate — so if you downloaded any of those since v1.8.0, you already have
files named this way on disk.

**What upgrading does, and what it doesn't:**

- **The dashboard corrects itself immediately**, with no action from you. Titles
  are cleaned when displayed rather than stored, so Recently Added reads
  correctly the moment you're on v1.10.0 — including for files downloaded months
  ago.
- **New downloads get correct filenames.**
- **Existing files keep their filenames.** Nothing renames them; nothing needs to,
  because Plex shows titles rather than filenames and the `Artist - ` prefix that
  smart collections match on was never affected.
- **Settings → Clean Up Titles now repairs the Plex-side titles** of the
  already-affected files, which it could not do before — the tool calls the same
  cleaner that was broken. Verified against a real library: all 11 affected files
  in it clean up correctly, e.g. `Helena [ - 4K Film Restored]` →
  `Helena [4K Film Restored]` and `Famous Last Words [] [HD]` →
  `Famous Last Words [HD]`. Run it once after upgrading if you use Plex.

Brackets carrying real information — `[US Version]`, `[Live at Wembley]` — are
untouched, as they always were.

## The dashboard numbers look like numbers now

The stat cards used proportional digits, so a figure would visibly change width
each time the 60-second refresh updated it, and `24.10 GB` sat at a different
optical weight than `197` beside it. Everything that updates or lines up in a
column now uses tabular figures.

The "Added over time" chart had a worse version of the same problem: it was drawn
at a fixed internal size and then stretched to fit its panel, which scaled the
axis labels **horizontally but not vertically** — roughly 3× wider than tall on a
desktop window. That's the "sloppy font" you may have noticed. The chart is now
drawn at its true pixel size and redrawn on resize, so text renders at its
intended proportions, and month names (`Oct`, `Dec`, `Feb`) replaced the numeric
labels.

Also: months with nothing added now show a dimmed stub rather than nothing at
all, so an empty month reads as empty instead of looking like a rendering fault.

## "Added (30 days)" now tells you what it measures

Vidshelf has never recorded download timestamps — the tracker file holds video
IDs and nothing else — so this figure counts files by their **modification
time**. That's accurate for files Vidshelf downloaded and wrong for anything you
moved onto the NAS by hand. The card now carries an ⓘ marker explaining it,
sourced from the API response so the wording can't drift away from what the code
actually does.

Recording real download dates is a v2.0.0 change; it needs a data model that
exists to hold them.

## Plex sync percentage was overstated on some installs

When Plex hadn't reported an artist count, the dashboard fell back to the
filesystem's count for the denominator — which made the ratio compare a number to
itself and read as complete regardless of what Plex actually had. It now shows
`--` when Plex hasn't answered, because no number is better than a wrong one.

## Two dead fields removed from `/api/library/stats`

`largest_artist_bytes` and `scanned_at` were added in v1.9.0 and never read by
anything. If you built something against them, they're gone; everything else in
that response is unchanged.

## New: a pre-release drill, and tests that can see the page

This is the part meant to stop the v1.9.x pattern repeating.

**`tests/test_browser.py`** drives a real browser against a running instance and
asserts on what is rendered. It exists because of three specific bugs that Python
tests structurally cannot catch: the Top Artists bars that rendered at **0 px**
(the DOM was right, the widths were right, and one CSS property silently ignored
them), the refresh loop that quietly hammered YouTube, and panels stuck on
"Loading…" in a way that reads as an application fault.

It is **optional** — no Playwright in `requirements.txt`, nothing new to install
to run the suite, and it exits 0 with a `SKIP` line when a browser or a live
instance isn't available. That keeps this project's no-dev-dependencies rule
intact.

**`prerelease.ps1`** (Windows, Docker Desktop) runs the drill that CI can't: it
builds the image, starts a **throwaway** container on a spare port so your real
one keeps running, then verifies the media mount is a genuine network share
rather than the decoy volume Docker Desktop silently substitutes, that `utime`
and `chmod` succeed on files the container doesn't own — the exact syscall
v1.8.1 fixed and v1.6.1 broke without noticing — that a library scan returns real
numbers, that anonymous callers are rejected, and that the browser tests pass.
Finally it upgrades from the previous release's image on the same data directory.

It ends by printing **what it did not cover**. A real download and a real Plex
sync are still manual, and the script says so rather than leaving you to assume
a green run means everything was checked.

## Upgrading

```bash
docker compose pull && docker compose up -d
```

Or on Windows, `.\update.ps1`. No recreate needed, nothing to migrate.
