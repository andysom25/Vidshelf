**Security release.** Fixes issues found in a review of the whole project ahead of
further work, not by anyone reporting them. **Upgrading is recommended.**

Nothing here changes how Vidshelf behaves for you — no new settings, no
migration.

## Cross-site scripting via video titles (high)

**A downloaded video's title was rendered into the dashboard without escaping.**
Titles come from YouTube, so they are not under your control: a video titled with
markup — for example `<img src=x onerror=...>` — would execute script in your
logged-in dashboard as soon as it appeared in the Downloads list.

That mattered because a script running in your session could read your **Plex
token**, which the API returned in full.

Fixed on both sides:

- All server-supplied values are now escaped before reaching the page — titles,
  filenames, error messages, artist names and channel URLs. Nine sites in total.
- **The Plex token is no longer sent to the browser at all.** Both
  `/api/config` and `/api/plex/config` now report only whether a token exists.
  The interface never needed the value.

Changing your password still requires the current one, which limited what an
attacker could have done, and the notification webhook URL was already withheld.

If you're concerned you downloaded something crafted, rotating your Plex token
(Plex → Account → Authorized Devices) is the conservative move.

## Container capabilities (medium)

The container was granted **`SYS_ADMIN`**, one of the broadest Linux capabilities
there is — left over from an earlier design where the container mounted the
network share itself. It doesn't: Docker mounts the share on the host.

Verified by testing: a container with **zero** added capabilities reads *and*
writes the share correctly. `SYS_ADMIN` was being granted for nothing, while
meaningfully weakening the isolation between the container and your host.

`docker-compose.yml` now uses `cap_drop: ALL`. **If you run your own compose
file, remove `cap_add: SYS_ADMIN` from it.**

## Credentials on disk (low)

`config.json` — which holds your Plex token, admin password hash and session
signing key — was created world-readable (`0644`). Since the data directory is
mounted from your host, that meant any local user on the host could read all
three. It's now owner-only (`0600`).

Existing files are re-permissioned the next time Vidshelf writes config.

## Also

- ffmpeg is now invoked with `--` before output paths, so a video whose title
  begins with `-` can't produce a filename that ffmpeg misreads as an option.
- Three new automated checks fail the build if any of the above regress: an
  unescaped value reaching the page, the Plex token being returned by the API, or
  `SYS_ADMIN` reappearing.

## Reviewed and found sound

For completeness, these were examined and needed no change: no shell invocation
anywhere (`shell=True`, `os.system` and `eval` are all absent); path traversal via
artist names is blocked; the SSRF guard correctly rejects loopback, private
ranges and cloud-metadata addresses; login throttling and session cookie flags
are in place; and no credentials appear in the repository history.

## Upgrading

```bash
docker compose down && docker compose up -d    # full recreate: capabilities changed
```

A plain `up -d` is enough for the code, but capability changes need the container
recreated rather than restarted.
