**If v1.12.0's new sort and filter controls did not appear after you upgraded,
this is the fix. Upgrade, or hard-reload the page (Ctrl+Shift+R) — either works.**

## The new UI could be invisible after an upgrade

Vidshelf's HTML pages were served with **no cache headers at all**, so a browser
was free to keep reusing the copy it already had. Static files (JavaScript, CSS)
were always sent with instructions to re-check, so those updated correctly — but
the page they run inside did not.

After upgrading to v1.12.0 that combination meant the **new JavaScript running
against the previous release's page**. The sort and filter controls live in the
page, so they simply were not there, and the search help text still described the
old ranking. Meanwhile the version in the sidebar read v1.12.0, because that comes
from an API call the cached script still makes correctly — so the app looked
upgraded and broken at the same time.

Nothing was actually wrong with the release. It was a caching problem that looked
exactly like a failed one.

HTML responses now say `no-store`, so a browser fetches the page fresh every time.
Static assets keep their existing behaviour — they re-validate cheaply and are only
re-downloaded when they have genuinely changed, which is what keeps page loads
fast.

**This affected every release that changed the interface**, not just v1.12.0. It
was simply most visible on one that added new controls.

## Upgrading

```bash
docker compose pull && docker compose up -d
```

Or on Windows, `.\update.ps1`. If you would rather not upgrade right now, a hard
reload (Ctrl+Shift+R, or Cmd+Shift+R on a Mac) gets you the current page.
