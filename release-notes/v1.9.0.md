**The dashboard is now about your library.** It used to be four cards about
channel monitoring — which, if you mainly use the Music Video Finder, meant it
showed you `0`, `--`, `1` and `0.0 KB` and a lot of empty space.

## What's on it now

Four headline numbers — **artists, videos, library size, and how much you've
added in the last 30 days** — followed by four panels:

- **Added over time** — a bar chart of the last 12 months, so you can see when
  you were building the library and when you weren't
- **Plex health** — how many artists have a Plex collection and artwork, with a
  button through to the ones that don't
- **Top artists** — who takes up the most space, as a ranked bar list
- **Recently added** — the last 10 videos with how long ago they arrived

**Channel cards only appear if you have channels.** If you don't use channel
monitoring, that section is hidden entirely rather than showing you zeroes.

The dashboard refreshes itself every 60 seconds while you're looking at it, and
there's a ↻ button on Recently Added if you want to force a rescan after a
download.

### About the dates

"Added" is based on **file dates**, not a download log — Vidshelf has never
recorded when a video was downloaded, only that it was. That's accurate for
videos Vidshelf downloaded, but if you've moved or re-copied files on your NAS
by hand, their dates reflect the move rather than the download. A proper
download history is planned and needs a change to how Vidshelf stores things.

## Speed

All of the above comes from a single scan of your media folder, cached and
shared between every panel. A typical dashboard load went from around 1.6s to
0.05s, and the case where the cache had just expired — previously the slowest,
at over two seconds — is now instant, because the old numbers are shown while
fresh ones are fetched in the background.

A finished download clears the cache immediately, so new videos appear right
away rather than waiting for the cache to expire.

## Also

- The 60-second refresh no longer redraws panels whose data hasn't changed, so
  it doesn't flicker or interrupt what you're doing.

## Troubleshooting: a hanging page on Windows

Not a change, but worth knowing — this cost real time to track down.

If the dashboard hangs for ~30 seconds and browser DevTools shows scripts as
`(failed)`, while the container itself is running and its log is clean, the
cause is likely **WSL**, not Vidshelf. WSL's `wslrelay.exe` claims the IPv6
address for whatever port Docker publishes, and Windows tries IPv6 before IPv4 —
so your browser reaches WSL instead of Vidshelf. It accepts the connection and
never replies, which is why you get a long hang rather than an error.

Quick check:

```
curl http://127.0.0.1:5000/login    # works
curl http://localhost:5000/login    # hangs
```

If that's what you see, add this to `%UserProfile%\.wslconfig` and run
`wsl --shutdown`:

```
[wsl2]
localhostForwarding=false
```

Changing Vidshelf's port does **not** help — WSL follows it to the new port.

## Upgrading

```bash
docker compose pull && docker compose up -d
```

No recreate needed, and nothing to migrate.
