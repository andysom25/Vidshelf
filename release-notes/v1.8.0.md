**Music videos, properly.** This release started as a feature review and turned
into a bug hunt — three things that were already supposed to work didn't, all on
the music-video path. If you use the Music Video Finder, this is worth upgrading
for.

Channel downloads are unchanged. Nothing about your existing files moves.

## Age-restricted music videos work now

Vidshelf has supported a `cookies.txt` since v1.6.0, and Settings → System Health
tells you when it's found. **The music-video downloader was never actually given
it.** It was the only one of five download paths that missed out — channel
downloads, bulk downloads, scheduled checks and retries all had it.

So an age-restricted music video would just fail, with a raw yt-dlp error and
nothing explaining why. Now it works like everywhere else.

The same omission meant the **quality cap didn't apply** to music videos either.
If you'd set a cap to keep 4K off your NAS, music videos ignored it. They don't
now.

## Retrying a music video sent it to the wrong folder

Retrying a failed music video put the file in your generic downloads folder
instead of the artist's folder — so no artwork, no Plex collection, and it never
showed up on the Artists page. Silently: there was no error.

Fixed. Retries now go where the original attempt was headed.

**If you retried music videos before upgrading**, check your downloads folder for
stray files. Vidshelf won't move them for you — they're your files, and it
doesn't know which ones you meant to keep there.

## The "Music Video Plex Path" setting actually does something now

This is the awkward one. That Settings field was editable, it saved, it appeared
in the config file and the README — **and nothing read it.** The download
destination was hardcoded. If you'd pointed it somewhere specific, it never had
any effect.

There were two settings for one folder. Vidshelf has always really used the
artwork root (the one the Artists page, retention and Plex collections all read),
so that's now the only one, and the Settings field edits it.

**If your two values disagreed**, Settings will show a notice with both paths
after upgrading. **Nothing has been moved and nothing was adopted automatically**
— the old value might point at a completely different share, and that's not a
decision to make on your behalf. Saving a path dismisses the notice.

## Music video filenames are now "Artist - Song"

Vidshelf's Plex features — the per-artist smart collections, the designed title
cards, the artist-name cleanup — all key off a title that starts with
`Artist - `. That relied on whoever uploaded the video having named it that way.
Plenty don't, and when they don't, the collection silently matches nothing.

Music videos are now named at download time, using the artist you searched for:

- `Nirvana - Smells Like Teen Spirit (Official Music Video)` → `Nirvana - Smells Like Teen Spirit`
- `Closer` (no artist in the title at all) → `Nine Inch Nails - Closer`
- `＂Weird Al＂ Yankovic - Eat It` → `Weird Al Yankovic - Eat It`
- en-dash titles like `The Raconteurs – Steady, As She Goes` are handled too

This only affects **new** music-video downloads. Existing files keep their
names — the Plex-side title cleanup in Settings still handles those, as before.
Channel downloads keep the uploader's title exactly as they always have.

## Also

- Every API endpoint's login check is now enforced by a single shared decorator
  rather than being written out by hand in 58 places. Two of the last three
  releases involved an endpoint that was missing that check, or ran it too late;
  this makes both mistakes structurally impossible rather than a matter of
  remembering.
- Four new automated checks fail the build if any of the above regresses,
  including one that inspects every download call site. Each was verified by
  breaking the code on purpose and confirming the check catches it.

## Upgrading

```bash
docker compose pull && docker compose up -d
```

No recreate needed. The config change is applied automatically on first start,
your Plex connection and login session are preserved, and the old value is kept
in view (not discarded) if it conflicted.
